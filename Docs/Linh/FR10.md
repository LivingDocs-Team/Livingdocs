# FR-AI-10 Đề xuất cập nhật tài liệu khi code thay đổi

| Mục | Nội dung |
|---|---|
| Story / task Jira | LD-352; LD-353 Implement Documentation Update Suggestions |
| Người thực hiện | Nguyễn Thị Phương Linh |
| Thành phần | AI Service: `app/suggestions.py`, `app/suggestion_api.py`; dùng lại phân tích PR (LD-146), tìm tài liệu bị ảnh hưởng (LD-148), ngữ cảnh thay đổi code (LD-338) |
| Tác nhân | GitHub Integration Service (gửi PR), người duyệt tài liệu |

## 1. Mô tả

Khi một Pull Request đổi code, AI Service đề xuất **cụ thể** cần sửa tài liệu thế nào: với mỗi đoạn tài liệu phải đổi, đưa ra đoạn đang có (`original`), đoạn nên có (`proposed`), lý do, độ tin cậy và diff. Tài liệu xét gồm tài liệu đã lưu (FR-AI-06) và file Markdown của repository gửi kèm. Đề xuất được giữ lại để người duyệt xem; tài liệu chưa bị sửa.

## 2. Yêu cầu chức năng

| ID | Yêu cầu |
|---|---|
| FR-AI-10.1 | `POST /suggestions/updates` nhận cùng body với `POST /drift/context` (PR, file thay đổi, `docs`, `document_ids`, `repository_files`, `k_code`, `k_docs`) và thêm `output_language` (`vi`/`en`, mặc định `vi`, dùng cho Markdown của repository; tài liệu đã lưu dùng ngôn ngữ của chính nó) và `use_ai` (mặc định `true`). Trả `201` với một **lô đề xuất** (`id`, `source = code_change`, PR, `suggestions[]`, `warnings[]`). |
| FR-AI-10.2 | Đoạn tài liệu (passage) là phần nằm dưới một tiêu đề Markdown (cách tách của FR-AI-03). Mỗi đoạn có nhiều nhất **một** đề xuất, gộp mọi thay đổi code liên quan tới đoạn đó, để khi áp dụng không đè lên nhau. `target` ghi `source` (`document`/`repository`), `path` (file của phần tài liệu đã lưu, hoặc file Markdown), `document_id`, `title`, `version`, `line_start`, `line_end` (trong phần tài liệu / file). `original` đúng bằng các dòng đó. |
| FR-AI-10.3 | Luật sửa theo loại thay đổi: **đổi tên** → thay tên cũ bằng tên mới (theo ranh giới từ; endpoint: thay cả dạng `GET /carts/:id`), độ tin cậy 0,9; **đổi chữ ký** → viết lại lời gọi `tên(...)` với tên tham số mới (giữ kiểu nếu tài liệu ghi kiểu), bảng tham số: xoá dòng tham số bị bỏ, đổi tên/kiểu dòng tương ứng, thêm dòng cho tham số mới (kiểu từ chữ ký, các cột khác `-`), sửa kiểu trả về trên dòng "Giá trị trả về"/"Returns", độ tin cậy 0,8; **docstring đổi** → thay câu cũ bằng câu mới, 0,7; **xoá** → nếu đoạn là mục riêng của thực thể (tiêu đề có tên nó) thì xoá cả đoạn (`delete`, 0,85), nếu chỉ nhắc tên thì xoá các dòng có tên (0,5). Độ tin cậy của đề xuất = thấp nhất của các luật đã thực sự đổi chữ. |
| FR-AI-10.4 | **Thực thể mới** (chỉ với tài liệu đã lưu sinh từ chính file đó): thêm một mục mới (`insert`) ngay sau mục cuối cùng cùng loại (hàm sau "Các hàm"/"Functions", lớp sau "Các lớp"/"Classes", endpoint sau "API Endpoints", phương thức sau các phương thức của lớp), cấp tiêu đề bằng cấp các mục cùng loại; nội dung: tiêu đề, khối chữ ký (chỉ tên tham số), câu "Chưa có mô tả. Mới thêm (PR #n), cần bổ sung mô tả." và bảng tham số; độ tin cậy 0,6. |
| FR-AI-10.5 | Thay đổi hành vi mà luật không viết lại được (thân hàm đổi, docstring không đổi) → đề xuất `review`: `proposed = null`, `method = none`, độ tin cậy 0, lý do nêu cần kiểm tra lại đoạn đó. |
| FR-AI-10.6 | Có AI (`ANTHROPIC_API_KEY`) và `use_ai = true`: với mỗi đoạn không phải `delete`, gửi AI ngữ cảnh LD-338 của các thực thể liên quan, đoạn hiện tại và kết quả của luật; AI trả JSON `{"proposed", "reason"}`. Câu trả lời hợp lệ và khác đoạn cũ thì dùng (`method = ai`, độ tin cậy 0,75; đề xuất `review` thành `replace`); lỗi gọi AI hoặc câu trả lời sai → giữ kết quả của luật. |
| FR-AI-10.7 | Mỗi đề xuất có `diff` (unified diff `a/path` → `b/path`, rỗng khi `proposed = null`), `reasons`, `entities`, `changes`, `evidence` (`X1 path:dòng` của thay đổi code), `status = pending`. |
| FR-AI-10.8 | Lô đề xuất được giữ trong bộ nhớ (200 lô gần nhất). `GET /suggestions` (lọc `batch_id`, `status`, `document_id`), `GET /suggestions/{id}`, `GET /suggestions/batches/{id}`; không có → `404`. |
| FR-AI-10.9 | Không có tài liệu nào → cảnh báo "No documentation was given"; có tài liệu nhưng không đoạn nào phải đổi → cảnh báo "No documentation passage needs to change for this Pull Request.". |

## 3. API

| Method | Endpoint | Yêu cầu |
|---|---|---|
| POST | `/suggestions/updates` | FR-AI-10.1 – 10.7, 10.9 |
| GET | `/suggestions`, `/suggestions/{id}`, `/suggestions/batches/{id}` | FR-AI-10.8 |

Ví dụ một đề xuất:

```json
{"id": "3f9c0a1b2c4d", "operation": "replace", "status": "pending",
 "target": {"source": "document", "path": "shop/cart.py", "document_id": "…", "version": 1,
            "line_start": 35, "line_end": 53},
 "entities": ["get_cart_total"], "changes": ["signature_changed"],
 "reasons": ["signature is now `get_cart_total(cart_id: int, currency: str) -> float`",
             "parameters: removed `discount`, added `currency`"],
 "original": "### `get_cart_total`\n\n```\nget_cart_total(cart_id, discount)\n```…",
 "proposed": "### `get_cart_total`\n\n```\nget_cart_total(cart_id, currency)\n```…",
 "method": "rule", "confidence": 0.8, "evidence": ["X1 shop/cart.py:10-15"]}
```

## 4. Luồng chính

1. Phân tích PR → các thực thể bị đổi (LD-146).
2. Lấy tài liệu: tài liệu đã lưu (`document_ids`, mặc định tất cả) + Markdown trong `docs`; tìm các đoạn nhắc tới thực thể bị đổi (LD-148).
3. Gom theo đoạn, áp các luật (FR-AI-10.3 – 10.5); thực thể mới thì chọn chỗ chèn (FR-AI-10.4).
4. Có AI → viết lại từng đoạn từ ngữ cảnh LD-338 (FR-AI-10.6).
5. Lưu lô, trả `201`.

## 5. Luồng lỗi

| Trường hợp | Kết quả |
|---|---|
| Body sai (thiếu `files`, `output_language` không phải `vi`/`en`, `k_code` > 10) | `422` |
| Tài liệu đã lưu không tồn tại | Cảnh báo, bỏ qua tài liệu đó |
| AI lỗi / trả sai | Giữ kết quả của luật, không báo lỗi |

## 6. Quy tắc nghiệp vụ

- Tạo đề xuất **không** sửa tài liệu; tài liệu chỉ đổi khi người duyệt chấp nhận và áp dụng.
- Một đoạn — một đề xuất; xoá đoạn được ưu tiên hơn sửa trong cùng đoạn.
- Không bao giờ đề xuất tên, tham số hay hành vi không có trong kết quả phân tích code.

## 7. Tiêu chí chấp nhận

- **AC-AI-10.1:** `get_cart_total(cart_id, discount)` đổi thành `get_cart_total(cart_id, currency: str)` → đề xuất cho mục `get_cart_total`: khối chữ ký thành `get_cart_total(cart_id, currency)`, bảng tham số bỏ dòng `discount`, thêm `` | `currency` | str | - | - | `` sau `cart_id`, độ tin cậy 0,8.
- **AC-AI-10.2:** `count_items` đổi tên thành `count_cart_items` → tiêu đề, chữ ký và mô tả trong mục đều dùng tên mới, độ tin cậy 0,9.
- **AC-AI-10.3:** `clear_cart` bị xoá → đề xuất `delete` cho mục `### clear_cart`; README dòng "see `clear_cart()`" bị bỏ, độ tin cậy 0,5.
- **AC-AI-10.4:** Thêm `apply_coupon(code: str)` → đề xuất `insert` sau mục `fetch_cart` (mục hàm cuối), có `### apply_coupon`, bảng tham số `` `code` | str ``.
- **AC-AI-10.5:** AI trả JSON hợp lệ → `method = ai`; AI trả chữ không phải JSON hoặc lỗi → `method = rule`, nội dung giống khi không có AI.
