## 1. Mô tả
Mỗi phần tài liệu AI sinh ra gắn với **bằng chứng** (grounding evidence): đường dẫn file, dòng bắt đầu/kết thúc và đoạn code hoặc tài liệu làm căn cứ. Bằng chứng nằm trong báo cáo của job sinh tài liệu và được hiển thị ở mục **Grounding Evidence** cho Developer, Staff và Manager. Khi hoàn tất, Developer **nộp tài liệu đi review**: tài liệu được lưu thành phiên bản, tạo workflow và chuyển sang hàng chờ của Staff. Ngoài ra, Code Analyzer có API riêng để lưu bằng chứng kiểm thử (log, ảnh, kết quả test) và gói chúng thành submission.

```
Job sinh tài liệu -> /report: files[].entities[].evidence (E/C/D, path, line_start, line_end, excerpt)
Submit: POST /api/documentation/jobs/{jobId}/document -> POST /api/document-workflows -> POST /{id}/submit
        -> PENDING_STAFF_REVIEW -> Staff /review-evidence, Manager /evidence
```

| Method | Endpoint | Kết quả | Yêu cầu |

Ví dụ một bằng chứng trong `/report`:
```json
{
  "id": "E1",
  "kind": "source",
  "path": "app/services/cart.py",
  "name": "get_total",
  "line_start": 12,
  "line_end": 20,
  "excerpt": "def get_total(cart, currency):"
}
```

## 4. Luồng chính
1. Developer sinh tài liệu (FR-AI-03); trạng thái job chuyển `pending` → `running` → `completed`.
2. Tài liệu mở cùng mục **Grounding Evidence**: chọn một phần để xem file, số dòng và đoạn code làm căn cứ.
3. Developer bấm **Submit for review**: tài liệu được lưu thành phiên bản, workflow được tạo và submit.
4. Workflow chuyển sang `PENDING_STAFF_REVIEW`; Staff nhận việc và xem review evidence của đúng phiên bản đó.
5. Staff chuyển cho Manager; Manager xem grounding evidence trước khi phê duyệt.

## 5. Luồng lỗi

| Trường hợp | HTTP | Kết quả |
| :--- | :--- | :--- |
| Job chưa hoàn tất khi lấy kết quả | `409` | `{"detail": "Job is <status>"}` |
| Submit khi tài liệu không có phiên bản đọc được | `409` | `{"message": "The document has no readable version."}` |
| Phiên bản không có bằng chứng | `404` | `Review evidence is not available for this document version` / `Grounding evidence not found for this document version` |
| Tạo submission với evidence không tồn tại | `400` | Liệt kê các evidence ID không tồn tại |
| Submit submission không có evidence | `400` | Cần ít nhất 1 evidence |
| Submit submission không ở trạng thái `DRAFT` | `409` | `Submission đang ở trạng thái ..., không thể submit` |
| Evidence hoặc submission không tồn tại | `404` | `Evidence không tồn tại` / `Submission không tồn tại` |

## 6. Quy tắc nghiệp vụ
* Bằng chứng chỉ được trích từ dữ liệu có thật (kết quả phân tích code và tài liệu có sẵn). AI trích mã bằng chứng không tồn tại thì bị trừ điểm confidence (FR-AI-09).
* Phiên bản tạo ra khi sửa hoặc rollback kế thừa bằng chứng của phiên bản gốc (`evidence_from_version`, FR-AI-10).
* Sau khi submit, nội dung chỉ đổi qua quy trình review: Staff yêu cầu chỉnh sửa thì Developer tạo phiên bản mới và nộp lại.
* Ghi file luôn atomic (file tạm + đổi tên), không để lại file ghi dở.
