## 1. Mô tả
Developer chọn repository và template rồi yêu cầu sinh tài liệu. AI Service tạo một **job chạy nền**, dựng prompt từ kết quả phân tích code (FR-AST-02), template và ngữ cảnh truy xuất, rồi sinh tài liệu Markdown. Không có `ANTHROPIC_API_KEY` thì dùng bộ sinh offline dựa trên luật. Kết quả mở trong trình soạn thảo có các tab **Edit**, **Preview**, **Versions** và **Compare**.

```
Frontend -> Backend BFF -> GitHub Integration POST /api/repositories/{id}/documentation/generate
  -> AI Service POST /generate (202, job pending) -> chạy nền -> completed
Frontend hỏi /api/documentation/jobs/{jobId} -> lấy /result (Markdown) và /report (evidence, confidence)
```

| ID | Yêu cầu |

## 3. API

**GitHub Integration Service** (frontend gọi qua Backend BFF)

| Method | Endpoint | Kết quả | Yêu cầu |
| :--- | :--- | :--- | :--- |
| **POST** | `/api/repositories/{id}/documentation/generate` | `202 Accepted` + job | FR-AI-03.1, 03.2 |
| **GET** | `/api/documentation/jobs/{jobId}` | `200 OK` + trạng thái job | FR-AI-03.2 |
| **GET** | `/api/documentation/jobs/{jobId}/result` | `200 OK` + Markdown | FR-AI-03.4 |
| **GET** | `/api/documentation/jobs/{jobId}/report` | `200 OK` + evidence, confidence | FR-AI-03.4 |
| **GET** | `/api/documentation/templates` | Danh sách template | FR-AI-03.3 |

**AI Service** (gọi nội bộ)

| Method | Endpoint | Kết quả | Yêu cầu |
| :--- | :--- | :--- | :--- |
| **POST** | `/generate` | `202 Accepted` + job | FR-AI-03.1, 03.2 |
| **GET** | `/jobs/{id}`, `/jobs/{id}/result`, `/jobs/{id}/report` | Trạng thái / Markdown / báo cáo | FR-AI-03.2, 03.4 |
| **GET / POST / PUT / DELETE** | `/templates`, `/templates/{id}` | Quản lý template | FR-AI-03.3 |

Ví dụ body từ frontend:
```json
{ "templateId": "default", "outputLanguage": "vi" }
```

## 4. Luồng chính
1. Developer mở **Documentation Generation › Generated Documents**, chọn repository và template, bấm **Generate documentation**.
2. Frontend gửi yêu cầu; nhận job ở trạng thái `pending`.
3. Frontend hỏi trạng thái job định kỳ cho tới khi `completed`.
4. Frontend lấy Markdown và báo cáo; tài liệu mở ở tab **Edit**, Grounding Evidence hiển thị dòng code làm căn cứ.
5. Developer sửa nội dung, xem ở tab **Preview**, bấm **Save draft** hoặc **Create version**, so sánh ở tab **Compare** và tải về bằng **Export Markdown**.
6. Developer gửi tài liệu đi review (FR-EVI-04).

---

## 5. Luồng lỗi

| Trường hợp | HTTP | Kết quả |
| :--- | :--- | :--- |
| `template_id` hoặc phiên bản template không tồn tại | `404` | `{"detail": "Template '<id>' not found"}` |
| Job không tồn tại | `404` | `{"detail": "Job not found"}` |
| Lấy kết quả khi job chưa xong | `409` | `{"detail": "Job is <status>"}` |
| Job thất bại | `200` | Job có `status: "failed"` và lý do; frontend hiển thị lỗi, không hiển thị kết quả giả |

---

## 6. Quy tắc nghiệp vụ
* Sinh tài liệu chạy nền vì gọi LLM có thể mất nhiều thời gian; request không chờ đồng bộ.
* Không có API key hoặc LLM lỗi thì AI Service dùng bộ sinh offline (rule-based); kết quả vẫn có cấu trúc theo template.
* Mỗi phần tài liệu gắn với bằng chứng: `E` (code của chính thực thể), `C` (code liên quan), `D` (tài liệu có sẵn).
* Bản nháp, phiên bản tạo trong phiên và so sánh ở tab Compare chỉ nằm trong trang; phiên bản được lưu lâu dài khi tài liệu được lưu vào workflow.
