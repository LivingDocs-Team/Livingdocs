## 1. Mô tả
Sau khi LD-145 phát hiện tài liệu bị lỗi thời, LD-151 phân loại chi tiết từng phát hiện (finding). Mỗi finding vẫn thuộc một trong 3 loại của BR-49 (Referential, Signature, Semantic), và có thêm:
- `kind`: thay đổi cụ thể, ví dụ `parameter_removed`, `endpoint_moved`, `status_codes_changed`.
- `breaking`: cách dùng đang được tài liệu mô tả có còn chạy được hay không.
- `rules`: các luật đã quyết định độ nghiêm trọng.

Hệ thống cũng đọc phần tài liệu ngay sau chỗ nhắc tới thực thể, để tìm những gì tài liệu **vẫn còn ghi** theo code cũ (tham số đã xoá, kiểu cũ, giá trị mặc định cũ, exception, status code, giá trị, câu docstring cũ). Những đoạn này được đưa vào bằng chứng và làm tăng độ nghiêm trọng.

```
thực thể thay đổi (LD-146) + tài liệu bị ảnh hưởng (LD-148)
  -> drift.classify(hit)
       Referential  LD-152  drift_referential.py   xoá / đổi tên / chuyển chỗ / tham chiếu dòng cũ
       Signature    LD-153  drift_signature.py     tham số, kiểu, mặc định, thứ tự, kiểu trả về, hợp đồng
       Semantic     LD-154  drift_semantic.py      status code, exception, giá trị, docstring, cài đặt
  -> finding: type + kind + breaking + rules + severity + những gì tài liệu còn ghi (D evidence)
```

## 3. API

LD-151 không thêm endpoint mới. Các endpoint của LD-145 trả về thêm các trường phân loại.

| Method | Endpoint | Kết quả | Yêu cầu |
| :--- | :--- | :--- | :--- |
| **POST** | `/drift/changes` | `200 OK` + thực thể thay đổi, có thêm `aspects`, `parameter_changes`, `breaking`, `signals` | FR-AI-06.3, 06.4 |
| **POST** | `/drift/analyze` | `201 Created` + Drift Report; mỗi finding có `kind`, `breaking`, `rules`; summary có `by_kind`, `breaking` | FR-AI-06.1 → 06.6 |
| **GET** | `/drift/reports/{id}` | `200 OK` + báo cáo đã phân loại | FR-AI-06.1 |
| **POST** | `/api/repositories/{id}/drift/analyze` | `201 Created` + Drift Report (GitHub Integration Service, không đổi) | FR-AI-06.1 |

Ví dụ một finding trong `/drift/analyze`:
```json
{
  "id": "F1",
  "type": "signature",
  "kind": "parameter_removed",
  "breaking": true,
  "severity": "high",
  "rules": ["breaking change: medium", "documentation still shows the old signature: +1"],
  "entity": "get_cart_total",
  "before": "get_cart_total(cart_id: int, discount: float = 0)",
  "after": "get_cart_total(cart_id: int, currency: str = 'VND')",
  "document": {
    "path": "README.md",
    "matches": [
      { "line": 12, "kind": "name", "term": "get_cart_total" },
      { "line": 14, "kind": "parameter", "term": "discount" }
    ]
  },
  "evidence": [ { "id": "X1", "kind": "code_diff" }, { "id": "D1", "kind": "documentation" } ]
}
```

## 4. Luồng chính
1. LD-146 so sánh kết quả analyzer `before` / `after` (hoặc đọc diff) và ghi lại thay đổi của từng thực thể: `aspects`, `parameter_changes`, kiểu trả về cũ/mới, `breaking`, `signals` hành vi.
2. LD-148 tìm phần tài liệu nhắc tới thực thể đó (hit).
3. `drift.classify(hit)` chọn bộ phân loại theo loại thay đổi: xoá / đổi tên / file → Referential; đổi chữ ký → Signature (kèm Semantic nếu thân hàm có tín hiệu hành vi); đổi hành vi hoặc thực thể mới → Semantic.
4. Bộ phân loại xác định `kind`, `breaking`, đọc phần tài liệu sau chỗ nhắc tới thực thể (tối đa 25 dòng) để tìm những gì tài liệu vẫn còn ghi, và áp các luật độ nghiêm trọng (`rules`).
5. Finding được gắn bằng chứng (LD-149), sắp xếp theo độ nghiêm trọng, và tổng hợp vào `summary.by_kind`, `summary.breaking`.

## 5. Luồng lỗi

| Trường hợp | HTTP | Kết quả |
| :--- | :--- | :--- |
| Request sai định dạng hoặc trùng đường dẫn file | `422` | `{"detail": [...]}` / `{"detail": "duplicate file paths: ..."}` |
| Chỉ có diff, không có kết quả analyzer | `201` | Vẫn phân loại; khai báo Python/Java được đọc từ diff, độ tin cậy ×0.8 |
| Thay đổi không xác định được chi tiết (không rõ tham số nào) | `201` | Finding `kind = signature_changed` (dạng chung) thay vì một kind cụ thể |
| Tài liệu không còn ghi gì của code cũ | `201` | Không cộng thêm mức nghiêm trọng; `document.matches` chỉ có chỗ nhắc tên |
| Thực thể private (`_name`) | `201` | Vẫn báo nhưng giảm 1 mức nghiêm trọng |

## 6. Quy tắc nghiệp vụ
* **Breaking** = cách dùng mà tài liệu mô tả không còn chạy: xoá/đổi tên thực thể hoặc tham số bắt buộc, đổi kiểu, đổi thứ tự, đổi kiểu trả về, đổi HTTP method, đổi hợp đồng; với Semantic là đổi status code.
* **Độ nghiêm trọng** (Low < Medium < High < Critical):
  * Xoá/đổi tên thực thể: High (endpoint: Critical).
  * Signature breaking: Medium, không breaking: Low (endpoint +1).
  * Đổi hành vi: Low (đổi status code, exception hoặc docstring +1; từ 15 dòng thay đổi trở lên +1).
  * Tài liệu vẫn ghi chi tiết cũ: +1. Tên private `_name`: -1.
  * Tham chiếu dòng cũ: Low nếu chỉ lệch dòng, Medium nếu các dòng đó đã bị sửa.
* Chỉ tìm chi tiết cũ trong tối đa 25 dòng tài liệu sau chỗ nhắc tới thực thể (`PARAM_WINDOW`).
* Mọi `kind` phải thuộc danh sách `DRIFT_KINDS` của type tương ứng.
