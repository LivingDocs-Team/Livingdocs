# FR-AUTH-01 User Registration, Login & GitHub Connection

| Mục | Nội dung |
| :--- | :--- |
| **Story Jira** | LD-20 User Registration, LD-38 Login/Logout, LD-43 GitHub OAuth Authentication |
| **Task liên quan** | LD-53 GitHub Account Connection, LD-63 Repository Synchronization, LD-292 Auth UI |
| **Người viết đặc tả** | Lâm Gia Huy |
| **Mã nguồn** | Backend do thành viên khác triển khai (`backend/src/main/java/com/cnpm/backend/auth/`); kết nối GitHub và đồng bộ repository ở GitHub Integration Service (`GitHubConnectionController`, `sync/`) |
| **Tác nhân** | Người dùng chưa đăng nhập, Developer |

---

## 1. Mô tả
Người dùng đăng ký và đăng nhập bằng email/mật khẩu, hoặc đăng nhập bằng tài khoản GitHub (OAuth2). Đăng nhập tạo **session** phía server, lưu bằng cookie; mọi request ghi phải gửi kèm token CSRF. Sau khi đăng nhập, Developer kết nối tài khoản GitHub qua **GitHub App** để thêm repository vào workspace và đồng bộ mã nguồn.

```
Đăng nhập:  Browser -> Backend /api/auth/login  -> session cookie (+ XSRF-TOKEN)
GitHub SSO: Browser -> /oauth2/authorization/github -> GitHub -> Backend -> /api/auth/oauth2/success -> FRONTEND_URL/?oauth=success
Kết nối repo: Browser -> Backend BFF -> GitHub Integration /api/github/authorize-url -> GitHub App -> /api/github/callback
```

---

## 2. Yêu cầu chức năng

| ID | Yêu cầu |
| :--- | :--- |
| **FR-AUTH-01.1** | Đăng ký bằng username (3–50 ký tự), email hợp lệ, mật khẩu (6–255 ký tự), họ và tên. Tài khoản mới luôn có vai trò `DEVELOPER`. |
| **FR-AUTH-01.2** | Đăng nhập bằng email và mật khẩu; email được chuẩn hoá về chữ thường. Thành công thì tạo session và trả thông tin người dùng (id, email, username, họ tên, role). |
| **FR-AUTH-01.3** | Đăng nhập bằng GitHub (OAuth2 authorization code). Lần đầu tạo tài khoản `DEVELOPER` gắn với GitHub ID; GitHub không trả email thì dùng `github-<id>@users.noreply.github.com`. |
| **FR-AUTH-01.4** | `GET /api/auth/me` khôi phục phiên khi tải lại trang; chưa đăng nhập thì trả `401`. Đăng xuất huỷ session. |
| **FR-AUTH-01.5** | Developer kết nối GitHub App, xem các repository App được phép truy cập, thêm repository vào workspace và ngắt kết nối khi cần. Token GitHub được mã hoá AES-256-GCM trước khi lưu. |
| **FR-AUTH-01.6** | Đồng bộ repository thủ công: lấy thông tin repo, commit mới nhất, danh sách file, nội dung file Java/Python; lưu thêm các commit và Pull Request gần nhất. |

## 3. API

**Backend** (trình duyệt gọi trực tiếp)

| Method | Endpoint | Kết quả | Yêu cầu |
| :--- | :--- | :--- | :--- |
| **GET** | `/api/auth/csrf` | `200 OK` + token CSRF | FR-AUTH-01.2 |
| **POST** | `/api/auth/register` | `201 Created` + thông tin người dùng | FR-AUTH-01.1 |
| **POST** | `/api/auth/login` | `200 OK` + thông tin người dùng, tạo session | FR-AUTH-01.2 |
| **GET** | `/oauth2/authorization/github` | Chuyển sang trang uỷ quyền của GitHub | FR-AUTH-01.3 |
| **GET** | `/api/auth/oauth2/success` | Chuyển về `FRONTEND_URL/?oauth=success` | FR-AUTH-01.3 |
| **GET** | `/api/auth/me` | `200 OK` + người dùng hiện tại, hoặc `401` | FR-AUTH-01.4 |
| **POST** | `/api/auth/logout` | `200 OK`, huỷ session | FR-AUTH-01.4 |

**GitHub Integration Service** (qua Backend BFF)

| Method | Endpoint | Kết quả | Yêu cầu |
| :--- | :--- | :--- | :--- |
| **GET** | `/api/github/authorize-url` | `authorizeUrl` và `installUrl` của GitHub App | FR-AUTH-01.5 |
| **GET** | `/api/github/callback` | GitHub gọi về sau khi người dùng cho phép | FR-AUTH-01.5 |
| **GET / DELETE** | `/api/github/connection` | Trạng thái kết nối / ngắt kết nối, thu hồi token | FR-AUTH-01.5 |
| **GET** | `/api/github/repos/available` | Các repository GitHub App được phép truy cập | FR-AUTH-01.5 |
| **GET / POST** | `/api/workspaces/{workspaceId}/repositories` | Danh sách / thêm repository vào workspace | FR-AUTH-01.5 |
| **POST** | `/api/repositories/{id}/sync` | Đồng bộ repository với GitHub | FR-AUTH-01.6 |
| **GET** | `/api/repositories/{id}/sync/latest` | Kết quả lần đồng bộ gần nhất | FR-AUTH-01.6 |

Ví dụ body `/api/auth/register`:
```json
{
  "username": "lamhuy",
  "email": "huy@example.com",
  "password": "secret123",
  "firstName": "Huy",
  "lastName": "Lam"
}
```

## 4. Luồng chính
1. Người dùng đăng ký tài khoản (vai trò `DEVELOPER`) hoặc bấm **Sign in with GitHub**.
2. Backend xác thực và tạo session; frontend gọi `GET /api/auth/me` để lấy id và role, rồi hiển thị menu theo vai trò.
3. Developer mở **GitHub Integration › GitHub Connection**, cài và uỷ quyền GitHub App.
4. GitHub gọi về `/api/github/callback`; token được mã hoá và lưu.
5. Developer chọn repository trong **Repository List**, thêm vào workspace và bấm đồng bộ.
6. Hệ thống lưu kết quả đồng bộ, commit và Pull Request gần nhất để dùng cho sinh tài liệu và phát hiện drift.

---

## 5. Luồng lỗi

| Trường hợp | HTTP | Kết quả |
| :--- | :--- | :--- |
| Dữ liệu đăng ký sai định dạng (thiếu trường, email sai, mật khẩu < 6 ký tự) | `400` | Thông báo theo từng trường |
| Username hoặc email đã tồn tại | `409` | `{"message": "Username is already registered"}` / `"Email is already registered"` |
| Sai email hoặc mật khẩu | `401` | `{"message": "Invalid email or password"}` |
| Đăng nhập GitHub thất bại (từ chối cấp quyền, email đã thuộc tài khoản khác) | — | Chuyển về `/?oauth=error` |
| Gọi `/api/**` khi chưa đăng nhập hoặc session hết hạn | `401` | Frontend chuyển về trang Login |
| Request ghi thiếu hoặc sai token CSRF | `403` | Từ chối |
| Chưa kết nối GitHub | `409` | `GITHUB_NOT_CONNECTED` |
| Token GitHub hết hạn hoặc bị thu hồi | `401` | `GITHUB_REAUTH_REQUIRED`, giao diện nhắc kết nối lại |
| Lỗi đồng bộ từ GitHub | `4xx/5xx` | `REPOSITORY_NOT_FOUND`, `TOKEN_INVALID`, `RATE_LIMITED`… |

## 6. Quy tắc nghiệp vụ
* Không dùng JWT: danh tính lấy từ session phía server. Trình duyệt chỉ gọi Backend; Backend tự gắn `X-User-Id` và internal secret khi chuyển tiếp, header do trình duyệt gửi bị bỏ qua.
* Mật khẩu được mã hoá bằng `PasswordEncoder` trước khi lưu.
* Đăng nhập (GitHub OAuth App) và kết nối repository (GitHub App) là hai bước tách riêng: quyền đọc code chỉ được cấp khi người dùng chủ động kết nối.
* Token GitHub mã hoá bằng `TOKEN_ENCRYPTION_KEY` (32 byte, Base64), không bao giờ trả về trình duyệt.

---

## 7. Tiêu chí chấp nhận
* **AC-AUTH-01.1:** Đăng ký thành công tạo tài khoản `DEVELOPER`; trùng email hoặc username trả `409`.
* **AC-AUTH-01.2:** Đăng nhập đúng tạo session, tải lại trang vẫn giữ đăng nhập; đăng xuất thì `/api/auth/me` trả `401`.
* **AC-AUTH-01.3:** Đăng nhập GitHub lần đầu tạo tài khoản mới, lần sau dùng lại tài khoản theo GitHub ID.
* **AC-AUTH-01.4:** Sau khi kết nối GitHub, repository được thêm và đồng bộ, hiển thị nhánh mặc định và thời điểm đồng bộ gần nhất.
