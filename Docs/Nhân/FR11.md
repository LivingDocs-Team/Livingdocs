## 1. Mô tả

Collection thuộc một workspace và có thể gắn repository. Quyền quản lý kết hợp quyền theo vai trò và quyền workspace. Phần phân công được xác minh qua PR #155; audit chưa xác định Jira riêng cho phần này.

## 2. Yêu cầu chức năng

| ID | Yêu cầu |
|---|---|
| FR-COLLECTION.1 | Cho Developer đọc và Technical Lead đủ quyền tạo, sửa, xóa collection và thêm/gỡ tài liệu. |
| FR-COLLECTION.2 | Chỉ cho đổi hoặc gỡ repository khi collection đã trống. |
| FR-COLLECTION.3 | Cho phân công tài khoản đang hoạt động có quyền vào workspace; mỗi tài liệu có tối đa một người phụ trách trong mỗi workspace. |
| FR-COLLECTION.4 | Hiển thị cùng một phân công ở mọi collection chứa tài liệu đó. |

## 3. API và luồng xử lý

Từ Knowledge Base → Documentation Collections, gọi `/api/workspaces/{workspaceId}/collections`. Dùng `PUT /{id}` để cập nhật, `PUT`/`DELETE /{id}/documents/{documentId}` để thêm/gỡ tài liệu, và `PUT /{id}/documents/{documentId}/owner/{userId}` để phân công.

### Hợp đồng API

Các đường dẫn dưới đây tương đối so với `/api/workspaces/{workspaceId}/collections`.

| Thao tác | Input | Thành công |
|---|---|---|
| `GET /` | Workspace của người gọi. | Danh sách collection có `id`, `name`, `description`, `repositoryId`, `repositoryName`, `hasDocuments`. |
| `POST /`, `PUT /{id}` | `name` khác rỗng tối đa 120 ký tự, `description` tùy chọn tối đa 1000, `repositoryId` là UUID tùy chọn. | Tạo trả `201`, cập nhật trả `200`, kèm collection sau khi lưu. |
| `GET /{id}/documents`, `GET /{id}/document-candidates` | ID collection trong workspace. | Danh sách tài liệu đã gắn hoặc ứng viên theo API tương ứng; mỗi phần tử có `id`, `title`, `assignedOwnerId`. |
| `PUT /{id}/documents/{documentId}`, `DELETE /{id}/documents/{documentId}` | ID tài liệu cần gắn/gỡ. | `204`; gọi lại thao tác gắn/gỡ hợp lệ không tạo bản ghi trùng. |
| `PUT /{id}/documents/{documentId}/owner/{userId}`, `DELETE /{id}/documents/{documentId}/owner` | Tài liệu đã gắn; người nhận phân công phải đang hoạt động và có quyền vào workspace. | `204`; cập nhật/xóa phân công chung. |
| `DELETE /{id}` | ID collection. | `204`. |

- **FR-COLLECTION.5 — Áp dụng quyền ở mỗi yêu cầu.** Xác minh workspace được truy cập với quyền `OWNER` hoặc `MEMBER`. Developer được đọc; Technical Lead được đọc/ghi. Workspace ngoài phạm vi trả `404`, vai trò không phù hợp trả `403`.
- **FR-COLLECTION.6 — Giới hạn kho và tài liệu.** Repository mới phải đang kết nối và thuộc đúng workspace. Chỉ cho gắn tài liệu có Markdown thuộc repository của collection. Khi repository không còn khả dụng trong workspace, danh sách tài liệu và ứng viên rỗng.
- **FR-COLLECTION.7 — Bảo toàn liên kết khi cập nhật.** Chuẩn hóa tên bằng trim; kiểm tra trùng trong cùng workspace không phân biệt hoa thường. Khi sửa collection, so sánh repository cũ/mới và kiểm tra còn tài liệu trong cùng giao dịch đã khóa bản ghi collection. Dùng cùng khóa khi thêm hoặc gỡ tài liệu để yêu cầu song song không thay repository bên dưới một lần gắn tài liệu.
- **FR-COLLECTION.8 — Lưu phân công theo workspace.** Khóa duy nhất của phân công là cặp workspace và tài liệu. Gắn tài liệu ở hai collection trong cùng workspace hiển thị cùng `assignedOwnerId`. Gỡ tài liệu khỏi một collection chỉ gỡ membership; xóa phân công dùng endpoint owner riêng.

## 4. Luồng lỗi

Đổi hoặc gỡ repository khi collection còn tài liệu trả `409 COLLECTION_REPOSITORY_LOCKED` và giữ liên kết hiện tại. Tên collection trùng trả `409 COLLECTION_NAME_EXISTS`.

## 5. Tiêu chí chấp nhận

- **AC-COLLECTION.1:** Developer có thể đọc collection trong phạm vi quyền.
- **AC-COLLECTION.2:** API trả `409` và giữ liên kết khi thay đổi repository của collection còn tài liệu; vẫn sửa được metadata.
- **AC-COLLECTION.3:** API cho đổi repository sau khi gỡ tài liệu cuối.
- **AC-COLLECTION.4:** Đổi người phụ trách ở một collection được phản ánh ở collection khác trong cùng workspace.

| Ca chấp nhận | Thiết lập và thao tác | Kết quả quan sát |
|---|---|---|
| AC-COLLECTION.5 | Tạo `API Docs`, rồi tạo ` api docs ` trong cùng workspace. | `409 COLLECTION_NAME_EXISTS`. |
| AC-COLLECTION.6 | Hai collection cùng chứa một tài liệu; gán người phụ trách từ collection thứ nhất, đọc collection thứ hai, rồi gỡ tài liệu khỏi collection thứ nhất. | Collection thứ hai vẫn chứa tài liệu với cùng người phụ trách. |
| AC-COLLECTION.7 | Đổi repository trong lúc một yêu cầu song song gắn tài liệu từ repository cũ. | Kết quả cuối không có membership của tài liệu thuộc repository khác collection. |
